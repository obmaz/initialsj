# 모델 단독 제작

저장소의 `AGENTS.md`와 `docs/MODEL_PIPELINE.md`를 읽습니다. 제작 규격·API·예산의 정본은 `MODEL_PIPELINE.md`이며 여기에 수치나 절차를 복제하지 않습니다.

1. 사용자 요청에서 분류(`vehicles`·`props`·`buildings`), ID, 실척, 외형 요구와 허용 작업 범위를 정합니다. 기존 모델 개선이면 해당 팩의 `definition.tres`와 `SOURCE.md`를 먼저 읽습니다.
2. 시각 모델만 맡은 작업은 `models/<분류>/<id>/` 안에서 형상·치수·재질·이미지·출처를 완성합니다. 공통 모델 등록표는 없으므로 다른 팩이나 중앙 목록을 수정하지 않습니다.
3. 공통 기하는 `models/shared/`의 API를 사용합니다. 새로운 전용 표현은 팩 안에 구현하고 다른 차량·오브젝트의 빌더에 의존하지 않습니다.
4. 차량 물리·능력·니트로·오디오·코스 배치는 통합 영역입니다. 사용자가 통합 작업도 요청한 경우에는 그 범위를 따르며, 필요한 공통 API 변경은 모델 변경과 분리한 커밋으로 만듭니다.
5. 생성형 이미지는 문·창·광고 위치에 맞는 전용 UV·재질로 연결합니다. 임포트된 정적 모델은 노드·축·피벗 계약을 확인하고 출처·라이선스·실제 사용한 생성 자료를 팩에 기록합니다.
6. `tools/check_models.gd`로 해당 모델을 검사하고 `tools/preview_model.gd`로 실척·정면·측면·후면을 확인합니다. 저장소 참조 검사도 실행합니다. 결과 이미지는 `build/reports/`에 둡니다.
7. `.uid`·`.import`를 포함한 해당 모델 팩만 커밋합니다. 대체안·검토 캡처·미사용 리소스를 남기지 않습니다. 작성자·커미터는 `AGENTS.md`를 따릅니다.

새 시각 모델이 카탈로그에 등록되는 것과 플레이 가능한 차량·코스 배치를 추가하는 것은 서로 다른 통합 단계입니다. 완료 응답에는 모델 ID·변경 폴더·실척·검사 결과·추가 통합이 필요한 사항을 적습니다.
