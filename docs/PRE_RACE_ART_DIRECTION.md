# 시작 전 화면 원화 제작 기준

이 문서는 시작·모드 선택·차량 선택·트랙 선택·설정을 하나의 생성형 원화 계열로 제작하는 기준입니다. 현재 주행 HUD·결과 연출·차량 모델·물리는 이번 화면 원화 작업의 대상이 아닙니다. 실제 입력·저장·번역·안전 영역 계약은 [UI 기준](UI_DESIGN.md)과 [개발 지침](../AGENTS.md)을 따릅니다.

## 공통 모습

밝은 낮의 해안 정비소를 게임의 입구로 사용합니다. 흰색 도장 패널, 청록 유리, 짙은 남색 글자, 작은 노랑 주버튼과 코랄 표시를 모든 화면에서 반복합니다. 차가운 검정 네온 설정창도 같은 밝은 계열로 전환합니다. 반사광·표면 두께·패널 이음새는 원화에 남기고, 번쩍이는 광선이나 가는 테두리를 계속 겹쳐 장식하지 않습니다.

| 역할 | 기준 색 | 사용 |
| --- | --- | --- |
| 글자 | `#142B49` | 제목·값·버튼명 |
| 보조 글자 | `#486378` | 단위·설명·부제 |
| 패널 | `#FFFDF7` | 빈 카드·빈 버튼·내용 영역 |
| 배경의 밝은 부분 | `#EDF7FA` | 하늘과 패널 사이 완충 |
| 선택 | `#17D5D6` | 선택 테두리·짧은 밑줄 |
| 주요 실행 | `#FFDF45` | 시작·주행·완료 |
| 보조 강조 | `#FB646B` | 작은 상태 표시·장식 일부 |

배경이 복잡한 곳 위에는 글자를 직접 배치하지 않습니다. 글자가 들어갈 영역은 무늬·반사광이 적은 밝은 면으로 생성합니다. 색 수와 버튼 규격을 유지하고 화면별 차이는 배경 조망과 콘텐츠 구획으로 만듭니다.

## 원화와 실제 콘텐츠의 경계

생성 이미지에는 로고·제목·버튼 글자·숫자·문자처럼 보이는 장식을 넣지 않습니다. 제목·차명·트랙명·설명·버전·설정 값은 번역 가능한 실제 텍스트입니다. 앱의 로고도 현재 번역·브랜드 정책을 유지하는 별도 레이어로 취급합니다.

차량 선택에는 실제 플레이 가능한 GLB 차량과 실제 튜닝 색상이 보여야 합니다. 원화의 차량 전시 공간과 하단 차량 카드 안쪽에는 차·차 그림자·차 실루엣을 그리지 않습니다. 바닥·리프트 주변·정비소의 깊이만 원화에 그리고 실제 차량 뷰포트가 그 위에 놓입니다. 성능 막대·선택 상태·볼륨 노브·토글·포커스도 실제 상태에서 그립니다.

현재 `master.png`의 버튼·패널·헤더·주버튼 픽셀을 재단하고 `backdrop.png` 환경판에 조립하여 다섯 통이미지를 만듭니다. 기존 입력 Rect를 유지하도록 조립한 화면별 이미지가 실제 배치의 비교 정본입니다. 생성 마스터는 공통 모양과 재질의 원본이며 그 전체 구도를 실제 메뉴의 입력 위치로 간주하지 않습니다. 각 통이미지 위에 실제 입력 영역·텍스트·값을 얹고, 같은 재단 부품을 가변 버튼·보조 메뉴에서도 공유합니다. 원화의 반사·모서리·비율을 비슷한 벡터 도형으로 다시 그리지 않습니다.

## 좌표와 안전 영역

설계 좌표는 `1280×720`입니다. 배경·버튼·텍스트·포커스·슬라이더는 [menu_layout.gd](../scripts/ui/menu_layout.gd)의 같은 안전 영역·배율·원점으로 표시하고, 입력도 그 변환의 역변환을 사용합니다. 화면 전체 너비에 이미지만 늘리고 입력은 기존 비율로 두는 방식은 사용하지 않습니다.

배경의 해안·차고는 바깥 여백까지 채울 수 있지만, 주요 조작 영역은 16:9 안전 콘텐츠 안에 둡니다. 모든 화면에서 뒤로가기의 기본 사각형은 `(60,16,220,80)`을 공유합니다. 주요 터치는 최소 `80` 설계 px 높이를 확보합니다. 414px 높이의 폰 콘텐츠에서는 약46px이며, 실제 Android 안전 영역·콘텐츠 크기에서도 44px 이상인지 확인합니다. 긴 번역은 최소 글자 크기와 두 줄을 먼저 사용한 뒤 마지막으로 말줄임합니다.

다음 사각형은 기존 입력 계약을 설명하는 표입니다. 실제 정본은 HUD 입력 Rect와 이를 읽어 베이크한 [layout.json](../art_sources/ui/coastal/layout.json)입니다. 문서의 표를 별도의 런타임 상수로 복제하지 않습니다. 생성 원본 재단 경계와 실제 화면의 목적지 Rect를 구분합니다.

| --- | --- | --- |

부트 스플래시는 준비 후 기존처럼 자동으로 메뉴로 이어집니다. 별도의 탭 대기 상태나 장식뿐인 시작 버튼을 만들지 않습니다. 설정은 메뉴·일시정지에서 공용 밝은 화면을 사용하고 기존 진입·저장·복귀 동작과 모달 역변환을 보존합니다. 주행 HUD·결과·일시정지 자체의 스타일은 이번 개편에서 변경하지 않습니다.

## 후속 원화 제작 조건

현재 마스터는 빈 차량 전시장과 공통 부품이 있는 원화입니다. 같은 원화를 참조한 환경판에서 UI를 제거하고 재단 조각을 재조립합니다. 원본은1672×941, 배포 통이미지는1280×720입니다. 차량 선택의 환경판은 전시대 위치에 맞게 좌우 반전하며, 각 화면의 입력 Rect는 바꾸지 않습니다. 아래 프롬프트는 후속 원화 제작에서 보존할 조건을 설명하며, 독립된 다섯 화면을 따로 생성하는 절차를 뜻하지 않습니다. 원본·출처·재단 경계는 [원화 정본](../art_sources/ui/coastal/README.md)을 따릅니다.

> 가로 16:9 모바일 아케이드 레이싱 게임의 실제 사용 가능한 UI 배경 원화를 제작한다. 밝은 낮의 해안 정비소, 청록빛 바다, 아이보리 도장 패널과 청록 유리, 작고 명료한 노란 주요 버튼, 남색 테두리, 아주 적은 코랄 강조. 따뜻하고 경쾌하며 고급스럽지만 과밀하지 않은 분위기. 카메라에 정면인 평면 UI, 배경 정비소에만 자연스러운 깊이. 모든 제목판·버튼·카드·수치 구역은 완전히 비워 두고 글자·숫자·로고·유사문자·워터마크를 절대로 넣지 않는다. 중앙 왼쪽에는 실제 게임 차량이 들어갈 넓고 비어 있는 전시 바닥, 오른쪽에는 실제 성능 텍스트가 들어갈 밝고 단순한 내용판, 하단에는 동일 규격의 빈 카드 네 개와 큰 이전·다음 버튼, 맨 아래에는 빈 보조 버튼 세 개와 노란 주요 실행 버튼 한 개. 차량·차 실루엣·차 그림자·성능 막대·체크 표시·선택 표시·슬라이더 노브는 그리지 않는다. 각 UI 부품의 수평·수직 모서리는 곧고 반복 부품의 치수는 동일해야 한다. 얇은 네온 선이 겹친 어두운 사이버 UI를 사용하지 않는다. 제공한 레이아웃의 영역과 바깥 여백을 유지한다.

생성기에 좌표를 적었더라도 결과가 정확한지 가정하지 않습니다. 실제 출력 종횡비와 부품 경계를 측정하고, 균일한 배율로 기준 캔버스에 맞춘 후 그 픽셀 경계를 좌표 자료에 기록합니다. 글자 흔적이 있거나 빈 차량 영역에 가짜 차량이 생기면 그 원화를 그대로 승인하지 않습니다.

## 이미지 부품으로 전환

- 원본은 `art_sources/ui/coastal/`에 보존하고 `.gdignore`로 엔진 가져오기를 막습니다. 원본 경로·해시·출력 크기·생성 설명·화면 역할·추출 좌표를 함께 둡니다.
- 배포 사본은 기존 [UI 폴더 구조](CODING_STYLE.md#런타임-폴더)에 맞춰 `assets/ui/pre_race/`에서 관리합니다. 실제 아트가 있는 파일만 등록하고 대체된 파일은 참조 확인 뒤 정리합니다.
- 첫 적용은 전체 16:9 바탕과 빈 프레임을 한 장으로 표시합니다. 단순히 기존 메뉴 위에 원화를 깔고 기존 패널을 다시 그리면 같은 부품이 중복되므로, 아트가 담당하는 바탕만 기존 그리기에서 제외합니다.
- 분리할 때는 제목판·보조 버튼·주요 버튼·카드·내용 패널의 순서로 진행합니다. 현재 [pre_race_art.gd](../scripts/ui/pre_race_art.gd)의 같은9분할 그리기를 사용합니다. [layout.json](../art_sources/ui/coastal/layout.json)의20px 모서리·테두리 여백을 보존하고 작은 목적지에서는 겹치지 않게 줄입니다. 사선·복잡한 그림이 있는 영역 전체를 무리하게 9분할하지 않습니다.
- 반투명 그림자·반사광을 자를 때는 실제 픽셀 여백을 포함하고, 아틀라스에는 최소4px의 이웃 여백을 둡니다. 각 슬롯에 글자를 포함시키지 않습니다.
- 버튼 텍스트와 포커스는 입력 사각형의 자식 역할을 유지합니다. 선택광은 원화의 빈 카드와 겹치는 별도 레이어로 두어 장면 전체 밝기를 깜빡이지 않습니다.

## 반응과 재미

통이미지는 고정하고, 실제 입력 Rect에 짧은 반사·안쪽 강조와 최대2px의 텍스트 눌림을 표시합니다. 반응은 [menu_feedback.gd](../scripts/ui/menu_feedback.gd)가 한 영역의 짧은 상태로 관리합니다. 선택·포커스는 해당 카드의 별도 청록 강조로 구분합니다. 눌림 장식을 따라 터치 영역을 옮기지 않으며, 설정 모달의 이미지·텍스트·입력은 같은 모달 변환을 공유합니다.

선택 카드는 청록 가장자리와 짧은 밑줄, 확정은 한 번의 버튼 효과음으로 구분합니다. 매 프레임 번쩍이는 모든 카드·화면 전체 이동·강한 확대·카메라 블러는 사용하지 않습니다. 모션 감소에서는 위치·크기 움직임을 생략하고 정적 테두리와 색으로 상태를 표시합니다. 효과음은 기존 효과음 볼륨과 ON/OFF를 따릅니다.

## 이미지 메모리와 수명

디스크 PNG/WebP 압축 크기와 GPU 메모리는 별도로 측정합니다. RGBA8 기준 `1280×720` 한 장은 약3.52MiB, `1920×1080`은 약7.91MiB입니다. 같은 크기 다섯 장을 동시에 유지하면 약17.6MiB·39.6MiB이며, 밉맵까지 생성하면 대략3분의1이 추가됩니다.

기본 배포 통이미지는1280×720을 기준으로 합니다. 원본은 고해상도로 보존할 수 있지만 글자가 없으므로 배경을 위해 모바일 GPU에 불필요한 고해상도를 유지하지 않습니다. 현재 통이미지 한 장만 미리 읽고 공통 부품을 공유합니다. 이전 통이미지는 직전 그리기 명령이 교체된 뒤 해제하며, 주행으로 넘어갈 때 메뉴 전용 참조와 미리 읽기 결과를 비웁니다. 시작·긴 로딩 아트도 필요한 동안만 읽습니다. 공통 부품과 같은 아틀라스는 한 자원을 공유합니다. 슬라이스를 만들었다고 원본과 복제 텍스처를 모두 상주시켜 이중 메모리를 소비하지 않습니다.

## 검증자의 판정 기준

검증자는 전체 작업에서 최대5회 검증합니다. 회차마다 바뀐 화면·이전 지적·실제 증거를 묶어서 판정하며 로그는 `build/reports/`에 둡니다. 현재 동작 문서에 회차별 이력을 쌓지 않습니다.

통과에는 원화와 실제 캡처를 같은 콘텐츠 영역으로 정렬한 비교, 폰·폴드의 전체 메뉴 경로 터치, 긴 번역, 선택·눌림·모션 감소, 선택 차량·코스·설정 값 유지가 필요합니다. 이미지 경계와 입력 영역의 어긋남, 글자 그림, 이중 패널, 화면마다 다른 뒤로가기 위치, 44px 미만의 주요 터치, 존재하지 않는 차량 그림, 가려진 차량·수치, 메뉴를 떠난 뒤 남는 대형 이미지 참조는 수정 대상입니다. 검증 통과는 코드 검사만으로 대체하지 않으며 측정하지 않은 실기기 프레임이나 시안의 완전 일치를 주장하지 않습니다.

## 보존 원화와 실제 재단 좌표

이번 제작의 원본은 [공통 원화](../art_sources/ui/coastal/master.png)와 [환경판](../art_sources/ui/coastal/backdrop.png)이며, 두 이미지 모두 1672×941입니다. 실제 재단 좌표·배치·해시는 [layout.json](../art_sources/ui/coastal/layout.json), 재생성 절차는 [베이크 도구](../tools/bake_pre_race_art.py)가 소유합니다. 아래 표는 이 자료를 읽기 쉽게 설명한 것이며 런타임의 별도 좌표 정본이 아닙니다.

재단 경계는 Pillow의 `(왼쪽, 위, 오른쪽, 아래)`이며 `(x,y,너비,높이)`가 아닙니다. 원화에서 네 조각을 추출한 뒤 정규화하고, 그 조각으로 기존 입력 위치에 맞춘 1280×720 통이미지를 만듭니다.

| 배포 부품 | 원본 재단 경계 | 정규화 크기 | 원본 모서리 마스크 |
| --- | --- | --- | --- |
| `button.png` | `(43,24,312,115)` | 256×96 | 17px |
| `panel.png` | `(40,165,460,585)` | 192×192 | 40px |
| `primary.png` | `(1010,786,1632,902)` | 512×96 | 25px |
| `header.png` | `(462,16,1385,124)` | 768×96 | 25px |

모서리 마스크는 원본 주변의 바닥·하늘을 투명하게 분리하기 위한 값입니다. 정규화한 부품을 늘리는 9분할 여백 20px와 구분합니다. 베벨·청록 금속·반사선·밝은 내용 면은 잘라낸 원화 픽셀을 사용합니다. 20px 모서리 영역을 고정하고 가운데 면과 직선 가장자리를 늘립니다. 목표 크기가 아주 작은 경우에는 `min(20,너비/3,높이/3)`으로 여백을 제한합니다. 원본과 대조할 때 마스크가 금속 테두리를 잘라내지 않는지 함께 확인합니다.

## 화면별 재조립 경계

[배포 화면](../assets/ui/pre_race/)의 `start.png`·`home.png`·`garage.png`·`courses.png`·`settings.png`가 현재 제품의 정적 배경이자 실제 비교용 화면 정본입니다. 생성한 마스터 한 장의 버튼 위치를 제품에 강제하지 않고, 마스터의 재료와 모서리를 유지한 채 기존 입력 사각형에 맞춰 부품을 재조립합니다.

- 시작은 원래의 자동 부트 흐름을 유지합니다. 상단 브랜드 영역과 하단 로딩 영역을 밝은 패널로 확보하고 실제 로고·버전·진행 표시·안내만 얹습니다.
- 모드 선택은 같은 제목 프레임·보조 버튼과 큰 두 내용판을 사용합니다. 실제 모드명·설명과 필요한 미리보기는 내용판 안쪽에 둡니다.
- 차량 선택의 환경판만 좌우 반전합니다. 원래 오른쪽에 있던 전시대를 기존 좌측 차량 표시 구역 가까이 두기 위한 처리이며, 차량 모델·캐시 렌더·카메라·주행은 바꾸지 않습니다. 성능판과 네 차량 카드의 숫자·모델·선택은 실제 콘텐츠입니다.
- 트랙 선택의 다섯 세로 내용판은 같은 `panel.png`로 만듭니다. 풍경·제목·길이·선택은 실제 레이어로 넣고 원화의 모서리·베벨 위를 덮지 않도록 안쪽에 배치합니다.
- 설정은 같은 아이보리 내용판과 청록 프레임을 사용합니다. 오디오·그래픽·조작의 값과 입력 높이는 기존 계약을 유지합니다. Android와 Web의 푸터 버튼 수가 달라 이 부분은 같은 부품으로 실행 시 그립니다.

빈 정본만으로는 실제 글자·차량·풍경과의 겹침을 판정할 수 없습니다. 첫 실제 캡처에서는 콘텐츠가 20px 모서리를 침범하는지, 작은 버전 배지에서 프레임이 글자를 압박하는지, 반전한 전시대와 실제 차량 접지가 어색하지 않은지 확인합니다. 아주 작은 버전 영역에는 프레임을 추가하는 대신 큰 설정판 위에 실제 버전 문자만 두는 것도 같은 디자인 계열 안의 선택입니다. 이 항목들은 디자인 자문 기준이며 검증자의 승인·회차 기록을 대신하지 않습니다.
