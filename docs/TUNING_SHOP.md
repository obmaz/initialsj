# 튜닝샵 설계안

이 문서는 다음 개발 단계의 화면·저장·모델 계약을 제안합니다. 현재 게임에 튜닝샵이 구현되었다는 뜻은 아닙니다. 설명용 HTML 화면은 `build/reports/tuning-shop-concept.html`에 두고 게임 내보내기에 포함하지 않습니다. 해당 화면의 차량은2D 도식이며 실제 GLB·생성형 리버리 에셋이 아닙니다.

## 사용자 경험

차고에서 차량을 고른 뒤 `튜닝샵`으로 들어갑니다. 중앙에는 선택 차량 한 대를 크게 보여 주고, 왼쪽은 도장·리버리·휠·리어윙 탭, 오른쪽은 현재 조합과 적용 상태를 둡니다. 모바일 가로 화면에서 조작 영역이 차량을 덮지 않게 배치합니다. 드래그로 차량을 돌리고 전면·측면·후면 시점을 바로 고를 수 있게 합니다.

| 탭 | 선택 내용 | 즉시 확인할 부분 |
| --- | --- | --- |
| 도장 | 기본 색상·색상 선택기·보조색·유광/무광/메탈릭 | 차체 도장면과 빛 반응 |
| 리버리 | 순정·스트라이프·해안 웨이브·레이싱 그래픽 | 보닛·좌우 문·뒤 펜더·후면의 연결 |
| 휠 |5스포크·분할 스포크·에어로 디스크와 림 색상 | 바퀴 확대 시점, 앞뒤의 간섭 없는 장착 |
| 리어윙 | 순정·낮은 덕테일·GT 윙·허용 차량의 윙 없음 | 후면 시점과 부스트 가동 시연 |

선택은 작업 중인 조합에만 반영합니다. `적용 전과 비교`는 저장된 조합을 잠시 보여 주고, `변경 취소`는 마지막 적용 상태로 돌아갑니다. `출고 사양`은 작업 중 조합을 순정으로 되돌리며, `내 차에 적용`을 눌러야 저장합니다. 화면을 떠날 때 미적용 변경이 있으면 저장·버리기·계속 편집을 구분합니다. 차량별 작업 중 조합은 미리보기 중 서로 섞이지 않습니다.

첫 단계는 **외형 튜닝**으로 제안합니다. 색·리버리·휠·윙을 바꾸어도 최고속도·가속·제동·그립·충돌체·휠베이스·차고가 변하지 않는다고 화면에 표시합니다. 성능 튜닝을 추가하려면 별도 능력치·기록 호환 정책을 설계합니다.

## 현재 코드와 연결할 부분

- [vehicle_catalog.gd](../scripts/vehicles/vehicle_catalog.gd)의 플레이 차량 ID는 `nimori`, `veltrix`, `ironvale`, `straud`이며 모델 팩은 각각 `hatch`, `wedge`, `muscle`, `gt`입니다. 교통용 `sport`는 사용자 튜닝 대상에서 제외합니다.
- [tour_passport.gd](../scripts/race/tour_passport.gd)는 현재 차량 ID별 도장·번호판 선택과 완주 해금을 저장합니다. [car.gd](../scripts/vehicles/car.gd)의 `apply_customization()`은 도장색·번호판을 적용하며 보호 상태의 재질 복제도 관리합니다.
- [garage_previews.gd](../scripts/ui/garage_previews.gd)는 현재 차량별 SubViewport를 만들고 선택된 카드를 한 번씩 그립니다. 튜닝샵의 연속 회전·부품 교체에는 별도의 **선택 차량 하나만 사용하는 미리보기**를 두는 편이 적합합니다.
- 기존 휠 중심·가동 스포일러·보호 도장·부스트 배기·바퀴 접지 보정 계약을 유지합니다. 튜닝 후 주행 차량과 차고 차량이 같은 조립 함수를 거쳐야 합니다.

## 리버리에서 먼저 해결할 UV 계약

**현재 차량에는 일반적인 사진 텍스처용 UV를 바로 사용할 수 없습니다.** [vehicle_body.gdshader](../shaders/vehicle_body.gdshader)는 `COLOR`를 표면색·도장 마스크, `UV`를 금속성·거칠기, `UV2`를 클리어코트·발광 강도에 사용합니다. PNG만 이 좌표에 붙이거나 외부 도구로 UV를 덮어쓰면 기존 금속·유리·발광 표현이 깨집니다.

권장 전환은 도장되는 면을 원본 GLB 안에서 `PaintShell`로 분리하고, 그 면에만 전용 UV0와 전용 재질 계약을 주는 것입니다. 비도장 유리·타이어·등·금속·실내는 기존 계약을 유지합니다. 기존 도장 면을 중복으로 겹쳐 놓지 않고, 원래 메시의 면을 이름 있는 파트로 분리해 전체 형상을 보존합니다. GLB 파일 자체와 편집 원본을 삭제하거나 생성물로 덮어쓰지 않습니다.

`PaintShell`은 좌우·보닛·루프·후면을 식별하는 전개도를 제공하고, 좌우 글자가 뒤집히지 않도록 글자 영역은 미러 UV를 쓰지 않습니다. UV 경계·봉제선·안전 여백을 표시한 템플릿과 실제 차량의6면 미리보기를 같은 팩에 둡니다. 마감은 도장용 재질의 금속성·거칠기·클리어코트 값으로 조절하며, 리버리 이미지에 광원·반사·그림자를 과하게 굽지 않습니다.

현재 도장 복구·보호 표시 코드는 공용 차체 셰이더의 동일성으로 대상을 찾습니다. 전용 리버리 셰이더를 도입할 때는 이름 있는 도장면 계약으로 확장하고, 원래 재질 복귀·보호색·미리보기의 재질 가열에도 새 셰이더를 포함해야 합니다. 텍스처만 보이고 무적 보호색이 적용되지 않거나, 차량을 바꾼 뒤 이전 리버리가 남는 상태를 막습니다.

리버리는 `기본 도장색 + 투명 그래픽 RGBA + 선택적 보조색 마스크`로 합성합니다. 창문·램프·번호판을 덮지 않고, 기본색을 바꾸어도 로고·문양의 색을 유지할 수 있게 합니다. 전면·후면·좌우를 따로 생성한 그림을 그대로 붙이기보다, 생성형 이미지를 그래픽 원료로 제작한 뒤 전개도에 맞춰 정리하고 이음새를 검수합니다. 이름·로고는 가상 브랜드를 사용하고 이미지별 출처·생성 방법을 팩의 `SOURCE.md`에 기록합니다.

## 팩 위치와 독립 작업

아래는 제안하는 배치이며 아직 없는 경로입니다. 세부 파일 형식은 구현 단계에 확정합니다.

```text
model_sources/vehicles/hatch/model.glb      보존하는 편집 원본, PaintShell·연결점 편집
model_sources/vehicle_parts/wheels/...     교체 휠의 편집 원본
model_sources/vehicle_parts/wings/...      교체 윙의 편집 원본

models/vehicles/hatch/
  definition.tres                          기본 차량의 정본
  model.tscn                              기본 차량 조립
  tuning.tres                             이 차량의 호환 부품·맞춤 치수·소켓
  liveries/coast_01/                       차량 전용 이미지·마스크·재질·썸네일
  SOURCE.md                               원본·이미지·변경 출처

models/vehicle_parts/wheels/five_spoke/     독립 GLB·씬·치수·재질·출처
models/vehicle_parts/wings/gt_low/          독립 GLB·씬·장착 피벗·출처
scripts/vehicles/vehicle_customization.gd  검증된 ID로 외형을 조립하는 어댑터
scripts/ui/tuning_shop.gd                  선택·미리보기·적용·취소
```

차량별 리버리는 각 차량 팩 안에서 소유하고, 공유 휠·윙은 부품 팩이 소유합니다. 모델·이미지 제작자는 해당 팩만 수정합니다. 저장·UI·재질 어댑터 통합은 별도 작업으로 나누어 공용 파일 충돌을 줄입니다. 중앙 배열에 모든 이미지·메시를 `preload`하지 않고 정의에는 ID·경로 문자열만 기록합니다. 현재 자동 탐색 모델 카탈로그에 부품 분류를 추가할지, 튜닝 전용 카탈로그로 분리할지는 통합 단계에서 한 곳으로 정합니다.

**원본 보존은 [모델 파이프라인](MODEL_PIPELINE.md)과 [원본 관리 규칙](../model_sources/README.md)이 우선입니다.** `models/`의 생성 GLB를 직접 편집하지 않습니다. 원본을 수정하고 승인된 원본 변경을 최적화 도구로 생성한 다음 해시·피벗·재질을 검증합니다. 미사용 부품으로 보인다는 이유로 편집 원본을 삭제하지 않습니다.

## 부품 연결과 실척

| 대상 | 고정 계약 | 가변 부분 |
| --- | --- | --- |
| 휠4개 | `wheel_fl`, `wheel_rl`, `wheel_fr`, `wheel_rr`, 원점=휠 중심, 로컬 `+Y`=회전축 | 림 형상·색·마감 |
| 휠 맞춤 | 차량의 기존 반경·폭·중심·접지면, 바퀴 회전 속도와 접지 보정 | 규격에 맞춘 모델별 시각 조립 |
| 리어윙 | 차체에 고정된 후면 소켓·장착 폭·트렁크 여유 | 윙 형상·높이·재질 |
| 가동 에어로 | 원래 휴지 변환·부스트 가동 규칙 | 지원하는 윙만 정해진 범위로 움직임 |

휠 교체는 기존 피벗 노드를 없애지 않고 메시·재질을 교체하는 방식을 우선합니다. 타이어 외경과 폭은 차량 규격에 고정하고, 최초에는 림 디자인만 달리합니다. 시각 휠을 크게 보이게 하려고 충돌체·`wheel_radius`·차고·접지 계산을 바꾸지 않습니다.4개 바퀴는 하나의 메시 자원을 공유합니다.

윙은 차종마다 소켓 변환·폭·장착 가능 높이·고정형/가동형 여부를 선언합니다. 현재 `active_aero`는 `MeshInstance3D` 하나이므로, 여러 조각을 가진 윙을 지원할 때는 통합 작업에서 `Node3D` 가동 루트를 도입하고 그 아래 메시를 조립합니다. 현재의 부스트 가동 원점·회전·복귀를 보존합니다. 고정 덕테일이나 윙 없음에 원래 가동 변환을 무조건 적용하지 않습니다. 모델별 호환 목록으로 루프·차체·배기구와의 간섭을 막습니다.

## 저장과 적용

차량 ID를 키로 삼은 별도 버전 있는 설정을 제안합니다. 도로에서 보이는 주행 차량·차고·결과 화면의 차량이 같은 저장값을 읽습니다. 저장에는 임의 파일 경로 대신 검증된 부품·리버리 ID만 둡니다.

```json
{
  "schemaVersion": 1,
  "vehicles": {
    "nimori": {
      "paint": "#E9EEE9",
      "secondaryPaint": "#F3C352",
      "finish": "gloss",
      "liveryId": "coast_01",
      "wheelId": "five_spoke",
      "wheelFinish": "graphite",
      "wingId": "stock",
      "plateId": "STOCK"
    }
  }
}
```

설정은 `user://vehicle_customization.cfg` 등 전용 파일에 두고 적용 순간에만 임시 파일→원자 교체로 저장합니다. 주행 중이나 색상 슬라이더를 움직일 때 파일을 쓰지 않습니다. 해금은 `TourPassport`가 계속 소유하고 새 저장은 외형 선택만 소유합니다. 기존 도장·번호판은 한 번 마이그레이션하되 완주·메달·고득점 자료를 초기화하지 않습니다. 없는 ID·비호환 부품·손상된 값은 순정으로 안전하게 표시하고 설정 파싱 오류로 주행을 막지 않습니다. 새 스키마를 모르는 구버전은 기존 자료를 덮어쓰지 않는 정책이 필요합니다.

최초에는 기본 도장색·순정 부품을 자유롭게 제공하고, 특별 리버리·명판을 투어 성과 보상으로 연결하는 안을 추천합니다. 자유 색상 선택기 때문에 과거 해금 도장색과 시각적으로 같은 색을 만들 수 있다는 점을 인정하고, 기존 색 해금 이력을 제거하지 않습니다. 실제 재화·판매·확률형 해금은 이번 제안에 포함하지 않습니다.

## 프레임·메모리 예산

- 미리보기 월드는 하나, 선택 차량은 하나만 유지합니다. 드래그·선택 변화가 없으면 SubViewport 갱신을 멈추고 필요할 때만 그립니다. 약한 GPU에서는 미리보기 해상도·MSAA·그림자를 먼저 낮춥니다.
- 색상 변경은 도장 유니폼만 바꾸고 재질·메시를 다시 만들지 않습니다. 적용 차량의 재질만 독립적으로 소유하며 공유 리버리 텍스처·메시를 나중에 수정하지 않습니다.
- 새 부품·텍스처는 비동기로 읽고 준비된 다음 한 번 교체합니다. 선택 순번으로 오래된 로딩 결과를 버리고, 교체 도중 잠깐 빈 차량이나 잘못된 차종의 부품이 보이지 않게 합니다.
- 리버리 카탈로그는 작은 썸네일만 읽습니다. 고해상도 이미지는 현재 선택과 다음 교체분만 보유하는 제한 캐시를 둡니다. 다수의 생성형2048px 이미지를 목록 진입과 동시에 GPU에 올리지 않습니다.
- 도장 그래픽은 통합된 표면 하나를 목표로 합니다. 옵션마다 겹친 Decal·투명 셸·실시간 반사·새 광원을 더하지 않습니다. 주행에서 휠·윙 LOD와 기존 차량 표시 거리 규칙을 유지합니다.
- 리버리는 기본2048px, 저사양1024px와 밉맵·모바일 VRAM 압축을 검토합니다. 정확한 예산은 실제 차량 UV와 대상 Android 기기의 측정값으로 확정하고 프레임 안정화 결과에 맞춥니다.
- 튜닝샵을 나가면 임시 미리보기·대기 로딩·미적용 재질 참조를 정리합니다. 레이스 도중 원본 텍스처를 동기 로드하거나 튜닝 설정을 저장하지 않습니다.

## 단계와 수용 기준

1. **기반:** 도장면 UV·부품 소켓·단일 미리보기·차종별 저장과 기존 도장/번호판 이관을 먼저 검증합니다.
2. **첫 콘텐츠:** 차종별 순정+리버리3종, 호환 휠2종과 림 색, 순정+윙2종을 제작합니다. 실제 생성형 전용 이미지는 이 단계에서 제작·검수합니다.
3. **화면 통합:** 적용 전 비교·취소·차량 전환·뒤로가기·패드/터치 조작을 연결하고 주행 차량에 같은 조합을 적용합니다.
