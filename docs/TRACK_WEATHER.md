# 트랙 날씨와 시간대 검토

트랙마다 `clear`·`rain`과 `day`·`dusk`·`night`를 선택하는 기능은 구현 가능합니다. 현재 선택 UI나 트랙별 저장 설정은 없습니다. 투어의 지역 메타정보와 별도로 트랙 ID별 환경 설정을 두고, 코스 진입 전 로딩에서 확정하는 방식이 적합합니다. 달리는 중 실시간 변경은 초기 구현 범위에서 제외하는 편이 안정적입니다.

## 현재 연결과 필요한 변경

| 구성 | 현재 동작 | 선택 기능에 필요한 작업 |
| --- | --- | --- |
| 하늘·원경 | 코스 전용 고정 이미지, 항만의 달·협곡의 낮은 태양 방위 고정 | 각 코스의 낮·노을·밤 이미지와 태양/달 방위를 한 환경 프리셋으로 관리. 낮 이미지를 어둡게 하는 것만으로 밤을 표현하지 않음 |
| 주광·안개 | [race_lighting.gd](../scripts/rendering/race_lighting.gd)의 트랙 번호 분기. 투어에는 메타정보 전환 존재 | 트랙별 프리셋과 시간대 합성 경로로 교체. 현재 투어의 `dusk`도 별도 색·광원 값이 필요 |
| 헤드라이트 | [race.gd](../scripts/race/race.gd)의 지역명 `neon`·`night`와 터널 판정 | 선택한 시간대로 플레이어·상대 차량·교통 차량을 함께 제어 |
| 비 입자 | [tour_weather.gd](../scripts/environment/tour_weather.gd)의 투어 모드 제한 | 트랙에서도 같은 제한된 입자 시스템을 사용하고 터널·유리 회랑 아래에서 비를 중지 |
| 젖은 노면 | [world_assets.gd](../scripts/rendering/world_assets.gd)의 투어 전용 `rain_wetness` | 활성 트랙의 독립 노면 재질에 적용. 공유 재질을 변경해 다른 코스까지 젖게 하지 않음 |
| 간판·창문·유도등 | 기존 야간 코스용으로 제작된 재질과 조명 | 주야간 발광 강도·가독성 검증. 밤에 모든 건물에 개별 실시간 광원을 추가하지 않음 |

비와 야간을 함께 선택할 때도 별도 확인이 필요합니다. 현재 투어 조명은 야간 값을 적용한 뒤 비 프리셋이 주광 세기를 다시 덮어쓰므로, 그대로 재사용하면 비 오는 밤이 의도보다 밝아집니다. 시간대의 기준 조명에 날씨를 보정하는 합성 순서가 필요합니다.

## 성능과 게임 규칙

- 비 입자·투명 유리·젖은 도로가 겹치면 폴더블 큰 화면에서 픽셀 중복 렌더 비용이 증가합니다. 비는 카메라 주변 한 시스템만 사용하고 성능 모드에서 양을 줄입니다. 투명 유리 회랑에서는 내부 비를 멈춰 중복 렌더와 빗줄기 관통을 방지해야 합니다.
- 야간 헤드라이트는 현재처럼 플레이어 위주로 실제 노면을 비추고 상대 차량은 발광 외형을 사용합니다. 차량마다 그림자 광원을 추가하면 특히16대 트랙2에서 부하가 커집니다.
- 첫 진입 시 비·발광·젖은 도로 셰이더의 컴파일로 끊길 수 있습니다. 선택한 프리셋의 자원만 로딩 단계에서 준비하고 모든 시간대 이미지를 상시 메모리에 보관하지 않습니다.
- 비에 따른 마찰·제동 변경은 별도 게임 규칙입니다. 처음에는 시각 효과로 제공하고, 물리까지 변경할 때는 기록을 코스·날씨별로 분리하거나 기존 기록과 비교 가능성을 명시해야 합니다. 시간대는 시야와 난이도에도 영향을 줍니다.
- 기존 도로·중심선은 그대로이므로 환경 설정만으로 곡률 캐시를 다시 만들 필요는 없습니다. 노면 형상·충돌 자료를 바꾸면 기존 재생성 계약을 따릅니다.

## 권장 적용 순서

1. 코스별 환경 프리셋과 저장 스키마, 선택 UI를 추가합니다. 잘못된 저장값은 기본 환경으로 복구합니다.
2. 하늘·원경·광원·안개·발광·헤드라이트를 시간대에 맞추고 비·젖은 노면을 연결합니다.
3. 유리 회랑·터널·다리와16대 상대 차량에서 비 관통, 가독성, 그림자 비용을 검사합니다.
4. 펼친 폴더블 고화질에서 트랙2의 GPU 프레임 시간·메모리·첫 진입을 측정하고 성능 모드와 비교합니다. 실제 기기 측정 없이60FPS를 보장하지 않습니다.

이 문서는 검토 결과이며 날씨·시간 선택 기능을 구현한 것으로 간주하지 않습니다.
