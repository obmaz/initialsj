# 시작 전 화면 원화 통합 계획

## 목표와 범위

시작·모드 선택·차량 선택·트랙 선택·설정은 글자 없는 생성형 원화의 실제 픽셀을 사용합니다. [차량 선택 마스터](../art_sources/ui/coastal/README.md)에서 공통 프레임을 재단하고, 기존 입력 사각형에 맞춰 다섯 화면의 투명 RGBA 프레임 통이미지로 재조립합니다. 기기 전체의 공유 환경판 위에 현재 프레임 통이미지 한 장과 실제 텍스트·차량·값·선택 상태를 얹습니다. 프레임 통이미지에는 환경을 굽지 않습니다. 화면별 베이크 이미지가 배치 비교의 기준이며, 마스터 원본은 공통 질감·프레임의 추출 기준입니다. 이 문서는 구현·검증·전달의 현재 계약이며, 검증 완료 보고서가 아닙니다.

엔진의 최초 스플래시 이미지는 공용 `backdrop.png` 환경판만 사용합니다. 실제 부트·긴 로딩의 LoadingOverlay는 환경판 위에 `start.png` 투명 프레임과 실제 제품명·진행 상태를 합성하고, 준비가 끝나면 기존처럼 자동으로 메뉴로 이어집니다. 모드 선택은 `MENU`, 트랙 선택은 `COURSES`, 차량 선택은 `READY`, 설정은 `SETTINGS`가 소유합니다. 시작 그림에 별도 탭 대기 상태나 눌러도 동작하지 않는 시작 버튼을 추가하지 않습니다. 화면 책임과 상태의 정본은 [race_state.gd](../scripts/race/race_state.gd)와 [race.gd](../scripts/race/race.gd)입니다.

| 대상 | 원화에 포함할 내용 | 실제 UI로 유지할 내용 |
| --- | --- | --- |
| 시작·부팅 | 밝은 해안 레이싱 배경, 타이틀의 빈 자리, 진입 장식 | 제품명·버전·로딩 안내·진행 상태 |
| 모드 선택 | 공통 헤더, TOUR·TRACK 카드 장식, 설정·여권 진입 장식 | 모드명·설명·실제 진입 버튼·진행도 |
| 차량 선택 | 공통 차고·쇼룸 배경, 차량·카드·능력치의 빈 영역 | 실제 GLB 미리보기·차명·성능·튜닝·카드 순환·출발 |
| 트랙 선택 | 공통 카드 틀, 트랙별 풍경 이미지, 하단 설정 영역 | 코스명·선택 상태·날씨·시간대·뒤로가기 |
| 설정 | 공통 헤더·패널·행·버튼 장식 | 음악·효과음 슬라이더, 토글, 화질, 조작 설정, 플랫폼별 버튼 |

시작 전 연결 화면인 여권·조작 설정·튜닝은 기존 기능과 복귀 경로를 보존하며, 공통 헤더·버튼·색을 같은 재단 아트로 공유합니다. 조작 설정도 같은 밝은 환경과 프레임을 사용합니다. 설정은 메뉴와 일시정지에서 같은 밝은 원화 화면을 사용합니다. 주행 HUD·결과·일시정지의 시각 스타일, 차량 모델·물리·코스·셰이더·원경 품질·고스트 표현은 이번 통합에서 변경하지 않습니다.

## PM·디자이너·개발자·검증자 하네스

| 역할 | 책임 | 인계 자료 |
| --- | --- | --- |
| PM | 화면 목록·우선순위·수용기준·회차 예산을 관리하고 변경 범위를 조정 | 이 계획, 화면별 동작 목록, 누락 항목 |
| 디자이너 | 기준 화면을 만들고 같은 스타일로 파생 원화·공통 부품을 제작 | 글자 없는 원본, 생성 조건, 색·규격, 재단 좌표 |
| 개발자 | 아트·입력·텍스트의 좌표를 공유하고 실제 상태·저장·입력·해제를 연결 | 실행 후보, 실제 화면, 터치·상태 검사 결과 |
| 검증자 | 원화와 실행 화면을 비교하고 가독성·조작·흐름의 통과 여부를 독립 판단 | 회차별 통과·실패·수정 지시, 근거 캡처 |

PM → 디자이너 → 개발자 → 검증자 → 개발자 수정 순서로 전달합니다. PM과 디자이너의 자체 점검, 개발자의 자동 검사는 검증자 회차와 구분합니다. 화면마다 검증 예산을 새로 만들지 않습니다.

검증자는 **이 통합 작업 전체에 최대 5회** 검토합니다. 한 회차는 해당 후보의 모든 대상 화면을 묶어 판정하고, 회차 번호·후보 커밋·원화 해시·검사 장치 크기·결함·재확인 결과를 `build/reports/pre-race-art/`에 남깁니다. 같은 후보를 나눠 요청하며 회차를 우회하거나 여섯 번째 검토를 요청하지 않습니다. 원화 생성·캡처 재시도 자체를 별도의 검증자 승인으로 기록하지 않습니다.

## 실행 순서

1. **화면과 동작 기준 고정**: 현재 폰·폴드 화면, 실제 클릭 영역, 저장 항목, 뒤로가기·게임 시작 경로를 기록합니다. 모든 화면에 공통으로 사용할 헤더·뒤로가기·주요 버튼 규격을 먼저 정합니다.
2. **원화와 재단 기준**: 차량 선택의 빈 전시장과 공통 부품을 담은 `master.png`, 같은 원화에서 UI를 제거한 `backdrop.png`가 색·조명·버튼·패널의 기준입니다. 글자 없는 원본에서 헤더·일반 버튼·주버튼·패널을 재단합니다. 재단 경계·원본 해시·재조립 좌표는 [layout.json](../art_sources/ui/coastal/layout.json)에 기록합니다.
3. **통이미지 적용**: [베이크 도구](../tools/bake_pre_race_art.py)가 재단 부품을 기존 입력 Rect로 조립해 `assets/ui/pre_race/`의 `start`·`home`·`courses`·`garage`·`settings` 1280×720 투명 RGBA 프레임 이미지를 만듭니다. 환경이 없는 프레임 이미지를 별도의 전체 화면 환경판 위에 합성하고, 기존 패널을 중복해서 그리지 않은 채 실제 입력·번역 텍스트·차량·값을 얹습니다. 원본 마스터의 다른 배치와 비교하지 않고, 각 화면의 베이크 이미지와 실제 캡처를 같은 콘텐츠 영역으로 맞춰 비교합니다.
4. **상태 반응 연결**: 통이미지 바탕은 고정하고, 실제 입력 Rect에 짧은 반사·안쪽 강조와 텍스트의 최대2px 눌림을 표시합니다. 선택·포커스는 별도 청록 강조를 사용합니다. 모션 감소·음량·음소거 설정을 따르고, 이전 화면의 포인터나 포커스가 다음 화면에 남지 않게 합니다.
5. **공통 부품 분리**: 같은 원본에서 재단한 `header`·`button`·`primary`·`panel`을 보조 메뉴와 플랫폼별 설정 푸터에 사용합니다. 9분할 원본 재단 여백은 `layout.json`의20px로 고정합니다. 목적지 여백만 `min(20, 너비/3, 높이/3)`으로 줄여 작은 버튼에서 모서리가 겹치지 않게 합니다. 목적지 크기 때문에 원본의 재단 경계를 함께 줄이지 않습니다. 통이미지에 이미 있는 프레임은 다시 덧그리지 않습니다. 정적인 화면 배치와 가변 UI의 공통 조각이 같은 아트를 사용하도록 유지합니다.
6. **모바일·번역 마감**: 폰·폴드·안전 영역·긴 번역에서 실제 버튼 크기와 글자·여백·화면 전환을 확인합니다. 코스·차량 추가에도 카드 순환과 실제 선택이 동작하는지 검사합니다.
7. **전달**: 필요한 로컬 공통 검사와 실제 화면 검사를 통과한 소스를 `main`에 푸시하고, Dropbox 기록에서 다음 번호를 정해 APK를 배포합니다. 실제 APK의 버전·서명·정렬·크기와 최신 JSON의 일치를 확인합니다.

### 검증자 회차 배분

| 회차 | 주 검증 대상 | 통과해야 할 내용 |
| --- | --- | --- |
| 1 | 원화·베이크·최초 실행 후보 묶음 | 다섯 화면의 스타일·빈 텍스트 영역·원본/재단 해시·배치·입력·기능 누락 |
| 2 | 앞선 지적을 반영한 통합 후보 | 베이크와 실제 배치의 일치, 입력·텍스트 좌표, 기본 이동 경로 |
| 3 | 상태 반응·공통 부품 분리 | 선택·눌림·포커스·비활성 상태, 재단 전후의 시각 보존, 저장 |
| 4 | 모바일·번역·수명 통합 | 폰·폴드·안전 영역·긴 문구, Back·패드·터치, 자원 해제 |
| 5 | 최종 회귀 확인 예산 | 앞선 결함의 해소, 최종 원화·소스·화면 근거의 일치 |

더 이른 회차에서 모든 기준이 충족되면 다섯 회차를 모두 소모하지 않습니다. 5회 후 차단 결함이 남으면 통과·배포 완료로 표시하지 않고, 잔여 결함과 미검증 범위를 보고합니다.

## 수용기준

- 원화·재단 아트·버튼·텍스트는 [menu_layout.gd](../scripts/ui/menu_layout.gd)의 1280×720 기준 좌표와 안전 영역 변환을 공유합니다. 부팅·시작 전 메뉴의 Window 콘텐츠 정책은 `EXPAND`를 사용해 기기 전체의 바탕을 그릴 수 있게 하고, 주행으로 들어갈 때 기존 `KEEP` 정책을 복원합니다. 배포용 `assets/ui/pre_race/backdrop.png` 한 장이 기기 전체를 종횡비 보존 cover로 채우며, 그 위의 투명 프레임 통이미지·텍스트·주요 입력은 안전 영역 안의16:9 콘텐츠에 맞춥니다. 중앙 이미지에 같은 환경을 다시 굽지 않아 중앙·바깥의 배경 배율 경계를 만들지 않습니다. 차량 선택에서만 환경판을 그리는 동안 수평 반전 변환을 적용하며, 프레임·입력·차량 카메라는 반전하지 않습니다. 배경 채우기를 위해 버튼까지 화면 너비에 늘리거나 별도 배율로 다시 계산하지 않습니다.
- 그리는 사각형과 실제 터치·패드 포커스 영역이 일치합니다. 원화의 빈 버튼 자리에 실제 입력 대상이 있고, 밝아진 장식과 다른 위치가 눌리지 않습니다. 화면 전환·중복 탭·드래그 해제·Android Back도 실제 경로로 검사합니다.
- 최소 가로 화면 896×414와 폴드 960×768에서 주요 조작 높이는 실제 콘텐츠 기준 44px 이상입니다. 상단·측면 안전 여백, 공통 뒤로가기 위치, 하단 버튼 행, 긴 번역의 최소 글자 크기와 말줄임을 확인합니다. 설계상의 높이만으로 실제 크기를 통과 처리하지 않습니다.
- 이미지에 제품명·제목·버튼·숫자·설정값·언어별 안내를 굽지 않습니다. 실제 텍스트를 번역한 뒤 렌더링하며 기존 저장 키·번역 키·버전 표시를 보존합니다. 기존 64개 Label 풀의 사용·숨김·상한을 확인하고 매 프레임 새 Label을 생성하지 않습니다.
- 차량 선택은 실제 선택한 GLB와 도장·튜닝 상태를 보여줍니다. 카드가 늘어나도 순환·선택·능력치·출발이 같은 차량을 가리키며 생성 그림의 가상 차량으로 실제 선택을 대체하지 않습니다.
- TOUR → 차량 선택 → 경기, TRACK → 트랙 선택 → 차량 선택 → 경기의 기존 흐름을 보존합니다. 차량 선택의 Back은 TOUR에서 모드 화면, TRACK에서 트랙 화면으로 돌아갑니다. 설정·여권·튜닝을 닫으면 진입한 화면으로 돌아가고 결과 이후의 기존 복귀 경로도 유지합니다. 설정은 메뉴와 일시정지에서 공유하므로 양쪽 진입을 검사하며, 모달이 확대·축소되는 동안에도 이미지·텍스트·입력 역변환이 일치해야 합니다.
- 음악·효과음 독립 볼륨, 화질, 모션 감소, 자동 가속, 조작 배치, 고스트·도색·번호판·튜닝, 트랙 날씨·시간대의 기존 기능과 저장을 보존합니다. Android에서 웹 전용 설치·전체화면 버튼을 표시하지 않습니다.
- 밝은 패널의 본문·보조 글자는 [UI 디자인 계약](UI_DESIGN.md)의 대비와 번역 맞춤 기준을 따릅니다. 그림 위 텍스트는 정해진 빈 영역 안에 배치하고 명암이 변하는 풍경과 겹치지 않습니다.
- 선택·눌림·포커스는 색 변화만으로 모호하게 표시하지 않습니다. 테두리·위치·밝기 등의 일관된 피드백을 함께 사용하며, 효과음은 효과음 볼륨을 따르고 모션 감소에서는 움직임을 줄입니다.
- 대형 메뉴 아트는 현재 투명 프레임 통이미지 한 장과 공유 환경판 한 장을 보유하고, 공통 재단 부품을 공유합니다. 이전 통이미지는 직전 렌더 명령이 교체된 뒤 놓고, 주행 진입 때 통이미지·환경판의 메뉴 참조와 미리 읽기 결과를 모두 해제합니다. 시작·긴 로딩 아트는 필요한 동안만 보유합니다. 다섯 통이미지를 동시에 예열하거나 매 프레임 다시 읽지 않으며, 별도 3D 패스·동적 그림자로 메뉴 장식을 재현하지 않습니다.

## 원본·근거 관리

생성 원화는 `art_sources/ui/coastal/`에 원본·해시·생성 설명·화면별 역할과 함께 보존하고 Godot 임포트·제품 내보내기에서 제외합니다. 배포용 통이미지·재단 아트는 `assets/ui/pre_race/`에 두고 [아트 출처](../assets/ui/GENERATED_ART.md)에 연결합니다. 재단 좌표는 원본 크기와 함께 기록해 같은 부품을 재현할 수 있게 합니다. 구현 후보의 원화·아트·소스가 같은 버전을 가리키는지 확인합니다.

원화 비교 캡처·오류·검증 회차·측정 자료는 `build/reports/pre-race-art/`에 둡니다. 자동 이미지 차이는 위치·크기·잘림을 찾는 보조 근거로 쓰며, 다른 장면의 실제 차량·동적 수치·폰트 렌더링까지 같은 픽셀이라고 주장하지 않습니다. 로컬 화면·브라우저 검증과 Android 실기기 실행 여부를 구분합니다.

배포 절차는 [APK 전달 스킬](../.agents/skills/dropbox-apk/SKILL.md)과 [Android 안내](ANDROID.md)를 따릅니다. 대상 없는 배포는 Dropbox APK 전달이며, 웹 게시·공개 릴리스·태그는 이 작업에 추가하지 않습니다.
