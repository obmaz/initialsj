# 차량별 사운드

**모든 차량은 자기만의 엔진(배기) 소리, 부스터 소리, 부스터 점화음, 드리프트 소리를 가집니다.** 다른 차량과 파일을 공유하거나 복사해 쓰지 않습니다. 차량을 추가하거나 이름·성격을 바꿀 때 이 문서의 절차를 반드시 따르고, 문서와 검사가 어긋나지 않게 유지합니다. 빠뜨리면 `tests/vehicle_audio_checks.gd`가 실패합니다.

## 현재 차량의 소리 성격

| 차량 | 엔진 (배기) | 부스터 | 점화음 | 드리프트 |
| --- | --- | --- | --- | --- |
| NIMORI H<br>(`nimori`) | 직렬 4기통. 밝고 부저 같은 소리. 기준 3300rpm | 맑은 터보 휘슬(약 2.8kHz)과 가벼운 바람 소리 | 밸브가 열리는 쉬익 소리에 상승하는 휘슬 | 좁고 가벼운 고음 휘슬 스킬(약 1.85kHz) |
| VELTRIX S<br>(`veltrix`) | 두 뱅크 10기통의 매끈한 고회전 괴성. 기준 5400rpm | 제트처럼 넓은 대역의 포효에 깊은 저음과 38Hz 크랙 | 140→38Hz로 떨어지는 묵직한 쿵 소리와 날카로운 균열 | 넓고 거친 고음 긁힘(약 1~4kHz), 빠른 떨림 |
| IRONVALE V8<br>(`ironvale`) | 크로스플레인 V8의 불규칙한 점화. 낮고 울렁이는 저음. 기준 3000rpm | 깊은 가스 포효, 11Hz 맥동, 낮은 슈퍼차저 휘슬 | 85→30Hz 쿵, 0.16초 뒤 백파이어 팝 | 낮고 고무가 긁히는 스크럽, 느린 저더 |
| STRAUD 6R<br>(`straud`) | 두 뱅크가 120°마다 번갈아 점화하는 수평대향 6기통. 날카로운 중고음. 기준 4200rpm | 트윈 터보 흐름에 약 1.1kHz 스풀 휘슬과 16Hz 웨이스트게이트 떨림 | 웨이스트게이트 쉬익, 내려가는 휘슬, 짧은 짖음 | 약 1.1kHz의 맑은 스킬과 3배 하모닉 |

소리는 모두 `tools/bake_vehicle_audio.py`로 직접 합성한 원본이며 외부 녹음을 쓰지 않습니다. 합성 후 같은 층끼리의 1/3옥타브 스펙트럼이 4dB 이상 다른지 자동으로 검사합니다. 스펙트럼 검사는 귀로 듣는 판단을 대신하지 못하므로, 새 소리는 아래 미리듣기로 반드시 들어 보고 조정합니다.

## 게임에서 소리가 나는 때

매핑 공식은 [vehicle_audio.gd](../scripts/vehicle_audio.gd) 한 곳에 있고, [racing_audio.gd](../scripts/racing_audio.gd)가 웹과 네이티브 양쪽에 같은 값을 전달합니다. 소리 설정이 OFF이거나 카운트다운·주행이 아니면(메뉴, 차고, 일시정지, 결과) 모든 층이 조용합니다.

| 층 | 재생 조건 | 볼륨(선형) | 재생 속도(피치) |
| --- | --- | --- | --- |
| 엔진 루프 | 카운트다운·주행 | 출발 대기 0.075, 주행 0.18, 부스트 중 0.21, 각각 `engine_gain` 배율 | `engine_pitch + rpm×engine_span + (기어−1)×engine_gear` (rpm은 0~1로 환산) |
| 부스터 루프 | 니트로 샷·셀·게이지 사용 중은 전체, 도로 부스트 패드·레인은 55% | 0.17 × `boost_gain` | `1 + boost_rise × 속도(90m/s를 1로)` |
| 점화음 (WAV) | 니트로가 시작되는 순간마다 한 번. 도로 패드는 공용 안내음 | 0.25 × `start_gain` | 1 |
| 드리프트 루프 | 드리프트 중 전체, 젖은 노면(물웅덩이)은 47% | 0.038 × `drift_gain` | `drift_pitch × (0.94 + 0.12×속도)` |

모든 루프의 기준 레벨(A가중 RMS)은 이전에 공용으로 쓰던 녹음과 맞춰 구웠습니다. 그래서 위 볼륨 상수는 그대로 의미가 있고, 차량별 `*_gain` 배율이 1에 가까울수록 같은 크기로 들립니다.

## 파일과 규칙

차량 `id`는 [vehicle_catalog.gd](../scripts/vehicle_catalog.gd)의 `"id"`(소문자 영문)이며, 파일 이름·웹 키·합성 레시피 키가 모두 이 `id`입니다.

| 파일 (`assets/audio/vehicles/`) | 내용 |
| --- | --- |
| `<id>-engine.ogg` | 엔진 루프. 2초, 모노 44.1kHz Vorbis. 한 루프에 4행정 사이클이 정수 번 들어가며 이음매가 없음 |
| `<id>-boost.ogg` | 부스터 루프. 2초 |
| `<id>-drift.ogg` | 드리프트 루프. 2초 |
| `<id>-boost-start.wav` | 점화음 한 번(0.5~0.8초) |
| `../web-loops.json` | 모든 차량의 세 루프를 base64로 담음 (`<id>-engine`, `-boost`, `-drift`). **직접 편집하지 않고** 합성 도구가 다시 만듭니다 |

- 루프 반복 설정은 가져오기 파일이 아니라 코드(`VehicleAudio.load_loop`)가 켭니다. 새 `.ogg.import`에서 `loop`를 바꿀 필요가 없습니다.
- 웹은 선택한 차량의 루프 세 개만 디코딩해 재생합니다(`web/file_audio.js`의 `setVehicle`). 차량 하나가 늘 때마다 `web-loops.json`이 약 95KB 커집니다.
- 점화음은 짧은 효과음이라 Godot 샘플 재생을 사용합니다.

## 카탈로그의 `audio` 항목

차량마다 `vehicle_catalog.gd`의 스펙에 `"audio"` 딕셔너리가 있어야 합니다. 파일 경로 네 개는 `res://assets/audio/vehicles/<id>-...` 형태의 전체 경로이며(저장소 검사기가 도달 가능성을 확인하는 데 필요), 숫자 항목의 허용 범위는 검사로 강제합니다.

| 키 | 뜻 | 범위 |
| --- | --- | --- |
| `engine`, `boost`, `boost_start`, `drift` | 위 표의 파일 | 전체 경로 |
| `engine_pitch` | 낮은 rpm·1단에서의 엔진 재생 속도 | 0.5~1.2 |
| `engine_span` | rpm이 0에서 1까지 오를 때 더해지는 속도 | 0.1~0.8 |
| `engine_gear` | 기어가 한 단 오를 때마다 더해지는 속도 | 0~0.15 |
| `engine_gain` | 엔진 볼륨 배율 | 0.5~1.6 |
| `boost_gain` | 부스터 볼륨 배율 | 0.4~1.6 |
| `boost_rise` | 속도가 오를 때 부스터 피치가 오르는 양 | 0~0.6 |
| `start_gain` | 점화음 볼륨 배율 | 0.3~1.6 |
| `drift_gain` | 드리프트 볼륨 배율 | 0.4~1.6 |
| `drift_pitch` | 드리프트 소리의 기본 피치 | 0.7~1.4 |

엔진 루프는 한 기준 rpm(레시피의 `rpm`)으로 구워 두고 재생 속도로 rpm을 흉내 냅니다. 유효 rpm은 `기준 rpm × 재생 속도`입니다. 현재 값으로는 NIMORI 약 3,000~5,300, VELTRIX 약 4,400~9,100, IRONVALE 약 2,300~4,300, STRAUD 약 3,600~7,000입니다. 차량의 `max_speed`와 속도감에 맞춰 `engine_pitch`와 `engine_span`을 정합니다.

## 새 차량을 추가할 때

사운드 항목만 정리한 체크리스트입니다. 차량 자체(모델·능력치)의 추가는 이 문서의 범위가 아닙니다.

1. **카탈로그**: `SPECS`에 스펙을 추가하고 `"audio"` 딕셔너리를 위 표대로 채웁니다. 파일 이름은 `<id>-engine.ogg`, `<id>-boost.ogg`, `<id>-boost-start.wav`, `<id>-drift.ogg`입니다.
2. **합성 레시피**: [tools/bake_vehicle_audio.py](../tools/bake_vehicle_audio.py)의 `VEHICLES`에 같은 `id`의 레시피를 추가합니다. 가장 성격이 가까운 차량의 레시피를 복사한 뒤, 엔진 종류(기통 수, 점화 순서, 배기 공진), 부스터의 질감, 점화음, 드리프트의 음색을 모두 **기존 차량과 뚜렷이 다르게** 바꿉니다. 숫자의 뜻은 파일 위쪽 주석에 있습니다.
3. **합성과 확인**: `python3 tools/bake_vehicle_audio.py --preview build/reports/audio`를 실행합니다. 레시피 누락, 클리핑, 기존 차량과 4dB 미만의 차이가 있으면 실패합니다. 통과하면 `build/reports/audio/<id>-demo.wav`를 귀로 듣고 마음에 들 때까지 레시피와 카탈로그의 배율을 조정합니다. 같은 레시피는 언제나 바이트까지 같은 파일을 만들므로 다시 구워도 안전합니다.
4. **가져오기**: `./tools/godot --headless --path . --editor --import --quit`을 실행해 새 파일의 `.import`를 만들고 함께 커밋합니다.
5. **출처**: 직접 합성한 소리는 [LICENSE.txt](../assets/audio/LICENSE.txt)의 `vehicles/` 항목이 이미 다룹니다. 외부 녹음이나 샘플을 쓰면 같은 파일에 출처·라이선스·변경 내용을 반드시 추가합니다.
6. **검사**: 아래 검사를 모두 실행합니다.
7. **문서**: 이 문서의 성격 표와 [GAMEPLAY.md](GAMEPLAY.md)의 차량 표에 한 줄을 추가합니다.

차량 수는 카탈로그의 `SPECS` 길이로 정해집니다. 차고 카드(한 줄에 균등 배치), 숫자 키 선택, 좌우 이동, 미리보기, 차고 문구(`tagline`, `role`)가 자동으로 따라가며, 차량을 순회하는 검사도 모든 차량을 다룹니다. 차고 카드 한 줄은 5~6대까지가 읽기 좋은 한계입니다.

## 소리를 듣고 조정하는 방법

`--preview DIR`은 차량마다 약 14초의 `<id>-demo.wav`를 씁니다. 게임과 같은 믹스이며, 조용한 층이 들리도록 전체를 약 9.5dB 키웠습니다. 앞 12초는 1~4단 기어로 엔진이 오르내리는 소리, 6~9초에 니트로 점화음과 부스터, 10~13초에 드리프트가 겹칩니다.

- 소리의 질감은 `tools/bake_vehicle_audio.py`의 레시피 숫자로 바꿉니다. 점화 위치·배기 공진은 엔진 종류를, `bands`는 노이즈의 음역을, `tones`는 휘슬·스킬의 높이를 정합니다.
- 크기와 피치 반응은 카탈로그 `audio`의 숫자로 바꿉니다. 소리를 다시 굽지 않아도 됩니다.
- 모바일 스피커는 약 100Hz 아래를 거의 재생하지 못합니다. 저음 위주의 소리(IRONVALE)는 중음의 윤곽이 있어야 휴대폰에서도 구분됩니다.

## 검사

```sh
python3 tools/bake_vehicle_audio.py --check
./tools/godot --headless --fixed-fps 60 --path . --script res://tests/race_test.gd
python3 tools/verify_repository.py
```

- `bake_vehicle_audio.py --check`는 카탈로그의 차량과 합성 레시피가 일치하는지, 네 파일이 모두 있는지, 클리핑·루프 길이·차량 간 스펙트럼 차이·`web-loops.json`의 최신 여부를 확인합니다. 합성은 시드가 고정되고 OGG 인코딩도 비트 단위로 고정되어, 다시 구워도 바이트가 같습니다.
- [vehicle_audio_checks.gd](../tests/vehicle_audio_checks.gd)는 `race_test.gd`에 포함되어 모든 차량의 `audio` 항목 완전성과 범위, 파일 존재, 다른 차량 파일의 재사용 여부(내용 해시), 합성 레시피 존재, 웹 루프가 파일과 일치하는지, 속도·상태에 따른 믹스, 선택한 차량으로 바뀌는 실제 플레이어의 스트림, 니트로 점화음, 음소거를 확인합니다.
- 웹 재생 경로는 Playwright와 Chromium, 실행 중인 Web export 서버가 필요한 `tests/web_audio_review.cjs`로 실제 브라우저에서 확인합니다. 차량당 엔진·부스터·드리프트 보이스 세 개가 모두 반복 재생되는지 봅니다.
- 실제 기기의 스피커 음색과 크기, 안드로이드 오디오 지연은 실기기에서 직접 확인해야 합니다.

## 비동기 선택과 종료

`web/file_audio.js`는 선택 요청마다 순번을 부여합니다. A→B→A처럼 같은 차량을 다시 선택해도 이전 디코딩 요청은 새 루프를 만들 수 없습니다. 종료 시 모든 루프와 연결을 끊고 입력 리스너·디코딩 캐시를 해제합니다. 이 수명 관리는 `node tests/audio_lifecycle_review.cjs`로 검사하며 차량별 음원 파일·프로필·합성 레시피를 공유하거나 변경하지 않습니다.

## 압축
소스 WAV(`-boost-start.wav`와 UI 효과음)는 편집용 비압축 파일이고, Godot가 가져올 때 QOA(`compress/mode=2`)로 압축해 내보냅니다. 효과음 5개는 108KB에서 24KB로, 점화음 4개는 약 235KB에서 약 45KB로 줄었습니다. 새 효과음을 넣을 때도 `.import`의 `compress/mode`를 2로 둡니다. 루프(엔진·부스터·드리프트)는 처음부터 OGG입니다.
